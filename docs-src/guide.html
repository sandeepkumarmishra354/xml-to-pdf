Guide

How xml2pdf documents are put together: page setup, how content flows and breaks across pages, styling, and templating with variables and loops.

Document structure

A document is a <document> root containing, in any order:

```xml ... ...
...
...
... ```

Rendering happens in stages:

  1. Parse. The XML is read and every element keeps its line number for error messages.
  2. Expand. ${variables} are substituted and <for-each> loops are unrolled.
  3. Validate. Elements and attributes are checked; unknown names, bad values and missing styles or images are errors.
  4. Lay out. Text is wrapped, tables are sized and content is split into pages.
  5. Render. Headers, footers and watermarks are added and the PDF is written.

Because variables are expanded first, you can use ${...} in any attribute or text. That includes colors, sizes and file names.

Layout & pagination

Flow

The blocks inside a page (<text>, <img>, <table>, <spacer>) are stacked from top to bottom inside the page's content area: the page minus its margins, minus any header or footer. When the next piece doesn't fit, a new page starts with the same size, margins and settings. Each <page> element always starts a new physical page.

  • Paragraphs break between lines.
  • Tables break between rows. Rows themselves are never split. Header rows (header="true") are kept with the first body row, and they repeat at the top of each continuation page unless repeat-header="false".
  • Images are never split. An image larger than the content area is scaled down to fit.
  • Vertical space (margin-top, margin-bottom, <spacer>) is dropped when it would land at the very top of a continuation page.
  • <page-break/> starts a new page. Consecutive breaks never produce blank pages.

Absolute positioning

Give a <text>, <img> or <table> an x and/or y to place it at exact coordinates instead of in the flow. Coordinates are measured from the top-left corner of the page (not the margin). A missing x defaults to the left margin, and a missing y to the top of the content area. Absolute blocks are drawn on the page the flow has reached at that point, and they don't take up space in the flow.

For absolute text and tables, width sets the box width. It defaults to the space from x to the right margin.

Text & fonts

Whitespace in text is collapsed the way HTML does it, so you can indent and wrap your XML freely. Use <br/> for a hard line break. A word too long for a line is broken at character boundaries.

```xml Normal, bold, italic, underlined, red and larger,
and a new line. ```

Loose text written directly in a <page>, <cell>, <header> or <footer> becomes an implicit paragraph.

Fonts

xml2pdf uses the standard PDF fonts, which every PDF viewer has built in, so nothing needs embedding:

font valueFont
helvetica, arial, sans, sans-serifHelvetica (default)
times, times-roman, times new roman, serifTimes
courier, courier new, monospaceCourier
zapfdingbatsZapfDingbats

Helvetica, Times and Courier each come in regular, bold, italic and bold-italic variants. ZapfDingbats (a set of symbols and dingbats) has a single variant.

Character set. The standard fonts cover Windows-1252: Latin-1 (é, ü, ñ, ß, …) plus €, “curly quotes”, ‘apostrophes’, – and — dashes, • and ™. Characters outside it, such as CJK, Cyrillic or emoji, can't be shown yet. Custom TrueType fonts with full Unicode are planned.

Styles

Text styling is set with style attributes, which work on almost every element. They cascade: document → page → block → table row → cell → inline span. Each level inherits from its parent and overrides what it sets itself.

```xml Inherits times and #222 but is 14pt and justified ```

Font, size, bold, italic, underline, color, alignment and line-height are inherited. margin-top, margin-bottom and bg apply only to the element they're set on.
